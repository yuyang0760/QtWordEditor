## 设计背景

### 当前系统的问题

当前的 `UnifiedCursorPosition` 设计存在以下问题：

1. **结构体冗余**：包含了所有可能的字段，但每次只用到一部分
2. **模式切换复杂**：需要同时维护多个指针（mathItem、mathContainer、mathNumberItem 等）
3. **缺乏扩展性**：如果要新增公式类型，需要修改整个结构体
4. **状态一致性问题**：多个指针需要保持同步，容易出错

### 为什么选择坐标路径系统

坐标路径系统具有以下优势：

1. **统一表示**：所有位置（文档、公式、嵌套公式）都可以用统一的方式表示
2. **优雅处理嵌套**：通过路径的方式自然地表示嵌套关系
3. **易于扩展**：新增公式类型无需修改核心数据结构
4. **状态一致性**：单一数据源，避免多个指针不同步的问题

## 系统目标

### 核心目标

1. **简化光标位置表示**：用统一的坐标路径替代复杂的多指针结构
2. **支持任意深度嵌套**：自然处理分数、根式、矩阵等复杂公式的嵌套
3. **易于扩展**：新增公式类型无需修改核心代码
4. **保持向后兼容**：提供与现有系统的兼容性接口

### 非功能性目标

1. **高性能**：路径操作的时间复杂度应为 O(1) 或 O(n)（n 为路径深度）
2. **内存高效**：避免不必要的内存分配
3. **类型安全**：编译期类型检查，减少运行时错误

## 核心概念

### 坐标路径（Coordinate Path）

坐标路径是描述从根元素到当前位置的一系列步骤。

**类比理解**：
- 坐标路径就像文件系统路径，如 `C:/Users/Documents/file.txt`
- 路径中的每一段代表在容器中的位置
- 通过路径可以唯一确定文档或公式中的任何位置

### 路径段（Path Segment）

路径中的每一个步骤称为路径段，包含以下信息：
- **容器**：当前所在的容器元素
- **子元素索引**：在容器中的第几个子元素
- **子元素内偏移**：在子元素内部的偏移量

### 路径深度（Path Depth）

路径段的数量称为路径深度。例如：
- 文档位置：深度 0（或 1，取决于设计）
- 简单公式：深度 1
- 分数的分子：深度 2
- 分数分子中的上标：深度 3

## 数据结构设计

### 1. 路径段（PathSegment）

```cpp
/**
 * @brief 坐标路径段
 * 
 * 描述路径中的一个步骤，包含：
 * - container: 当前所在的容器
 * - childIndex: 在容器中的子元素索引
 * - childOffset: 在子元素内部的偏移量
 */
struct PathSegment {
    MathItem* container = nullptr;      ///< 当前容器
    int childIndex = -1;                  ///< 子元素索引
    int childOffset = 0;                  ///< 子元素内偏移
    
    /**
     * @brief 检查路径段是否有效
     */
    bool isValid() const {
        return container != nullptr && childIndex >= 0;
    }
    
    /**
     * @brief 相等性比较
     */
    bool operator==(const PathSegment& other) const {
        return container == other.container
            && childIndex == other.childIndex
            && childOffset == other.childOffset;
    }
};
```

### 2. 坐标路径（CoordinatePath）

```cpp
/**
 * @brief 坐标路径
 * 
 * 描述从根元素到当前位置的完整路径
 */
class CoordinatePath {
public:
    /**
     * @brief 构造函数
     */
    CoordinatePath() = default;
    
    /**
     * @brief 从向量构造
     */
    explicit CoordinatePath(std::vector<PathSegment> segments)
        : m_segments(std::move(segments)) {}
    
    // ========== 路径操作 ==========
    
    /**
     * @brief 在路径末尾添加一个段
     */
    void push(PathSegment segment) {
        m_segments.push_back(std::move(segment));
    }
    
    /**
     * @brief 移除路径末尾的段
     */
    void pop() {
        if (!m_segments.empty()) {
            m_segments.pop_back();
        }
    }
    
    /**
     * @brief 获取路径末尾的段（可修改）
     */
    PathSegment& top() {
        return m_segments.back();
    }
    
    /**
     * @brief 获取路径末尾的段（只读）
     */
    const PathSegment& top() const {
        return m_segments.back();
    }
    
    /**
     * @brief 获取指定索引的段
     */
    PathSegment& at(size_t index) {
        return m_segments.at(index);
    }
    
    const PathSegment& at(size_t index) const {
        return m_segments.at(index);
    }
    
    /**
     * @brief 清空路径
     */
    void clear() {
        m_segments.clear();
    }
    
    // ========== 信息查询 ==========
    
    /**
     * @brief 获取路径深度
     */
    size_t depth() const {
        return m_segments.size();
    }
    
    /**
     * @brief 检查路径是否为空
     */
    bool isEmpty() const {
        return m_segments.empty();
    }
    
    /**
     * @brief 检查路径是否有效
     */
    bool isValid() const {
        if (m_segments.empty()) {
            return true; // 空路径也是有效的
        }
        for (const auto& seg : m_segments) {
            if (!seg.isValid()) {
                return false;
            }
        }
        return true;
    }
    
    // ========== 迭代器支持 ==========
    
    auto begin() { return m_segments.begin(); }
    auto end() { return m_segments.end(); }
    auto begin() const { return m_segments.begin(); }
    auto end() const { return m_segments.end(); }
    
    // ========== 比较操作 ==========
    
    bool operator==(const CoordinatePath& other) const {
        return m_segments == other.m_segments;
    }
    
    bool operator!=(const CoordinatePath& other) const {
        return m_segments != other.m_segments;
    }
    
private:
    std::vector<PathSegment> m_segments;  ///< 路径段列表
};
```

### 3. 新的光标位置（NewCursorPosition）

```cpp
/**
 * @brief 新的光标位置（使用坐标路径）
 * 
 * 整合了文档位置和公式坐标路径
 */
struct NewCursorPosition {
    // ========== 文档位置 ==========
    int blockIndex = -1;              ///< 块索引
    int offset = 0;                    ///< 块内偏移量
    
    // ========== 公式坐标路径（可选）==========
    std::optional<CoordinatePath> mathPath;  ///< 公式坐标路径
    
    // ========== 便捷查询 ==========
    
    /**
     * @brief 是否在文档模式
     */
    bool isDocumentMode() const {
        return !mathPath.has_value();
    }
    
    /**
     * @brief 是否在公式模式
     */
    bool isMathMode() const {
        return mathPath.has_value();
    }
    
    /**
     * @brief 检查位置是否有效
     */
    bool isValid() const {
        if (blockIndex < 0) {
            return false;
        }
        if (mathPath.has_value()) {
            return mathPath->isValid();
        }
        return true;
    }
    
    // ========== 比较操作 ==========
    
    bool operator==(const NewCursorPosition& other) const {
        return blockIndex == other.blockIndex
            && offset == other.offset
            && mathPath == other.mathPath;
    }
    
    bool operator!=(const NewCursorPosition& other) const {
        return !(*this == other);
    }
};
```

## API 设计

### 1. 路径构建 API

```cpp
// 示例：构建分数分子位置的路径
CoordinatePath buildFractionNumeratorPath(
    FractionItem* fraction,
    int numeratorIndex,
    int numeratorOffset
) {
    CoordinatePath path;
    
    // 第一层：分数容器
    path.push({
        .container = fraction,
        .childIndex = FractionItem::NumeratorIndex,
        .childOffset = 0
    });
    
    // 第二层：分子容器
    path.push({
        .container = fraction->numerator(),
        .childIndex = numeratorIndex,
        .childOffset = numeratorOffset
    });
    
    return path;
}
```

### 2. 路径导航 API

```cpp
/**
 * @brief 路径导航器
 * 
 * 提供在坐标路径中移动的便捷方法
 */
class PathNavigator {
public:
    explicit PathNavigator(CoordinatePath& path) : m_path(path) {}
    
    /**
     * @brief 向左移动
     */
    bool moveLeft();
    
    /**
     * @brief 向右移动
     */
    bool moveRight();
    
    /**
     * @brief 向上移动（进入上一级容器）
     */
    bool moveUp();
    
    /**
     * @brief 向下移动（进入下一级容器）
     */
    bool moveDown(MathItem* nextContainer);
    
private:
    CoordinatePath& m_path;
};
```

### 3. 路径访问者模式

```cpp
/**
 * @brief 路径访问者
 * 
 * 用于处理不同类型路径段的操作
 */
class PathVisitor {
public:
    virtual ~PathVisitor() = default;
    
    virtual void visit(RowContainerItem& container, int childIndex, int childOffset) = 0;
    virtual void visit(FractionItem& fraction, int childIndex, int childOffset) = 0;
    virtual void visit(NumberItem& number, int offset) = 0;
    // 新增公式类型只需添加新的 visit 函数
};

/**
 * @brief 应用访问者到路径
 */
void applyVisitor(const CoordinatePath& path, PathVisitor& visitor);
```

## 实现示例

### 示例 1：文档位置

```cpp
// 文档位置：第 2 个块，偏移 10
NewCursorPosition docPos;
docPos.blockIndex = 2;
docPos.offset = 10;
// mathPath 为空，表示在文档模式

assert(docPos.isDocumentMode() == true);
assert(docPos.isMathMode() == false);
```

### 示例 2：简单公式位置

```cpp
// 简单公式位置：在行容器的第 3 个子元素，偏移 5
NewCursorPosition mathPos;
mathPos.blockIndex = 2;
mathPos.offset = 0;

CoordinatePath path;
path.push({
    .container = rowContainer,
    .childIndex = 3,
    .childOffset = 5
});

mathPos.mathPath = std::move(path);

assert(mathPos.isMathMode() == true);
assert(mathPos.mathPath->depth() == 1);
```

### 示例 3：分数分子位置

```cpp
// 分数分子位置
NewCursorPosition fractionPos;
fractionPos.blockIndex = 2;
fractionPos.offset = 0;

CoordinatePath path;

// 第一层：分数容器
path.push({
    .container = fractionItem,
    .childIndex = FractionItem::NumeratorIndex,
    .childOffset = 0
});

// 第二层：分子行容器的第 2 个子元素，偏移 3
path.push({
    .container = fractionItem->numerator(),
    .childIndex = 2,
    .childOffset = 3
});

fractionPos.mathPath = std::move(path);

assert(fractionPos.mathPath->depth() == 2);
```

### 示例 4：路径导航

```cpp
// 假设当前在分数分子的第 2 个子元素，偏移 3
CoordinatePath path = ...;
PathNavigator navigator(path);

// 向右移动
navigator.moveRight();
// 现在在分数分子的第 2 个子元素，偏移 4

// 向上移动（退出到上一级）
navigator.moveUp();
// 现在在分数容器，子索引为 0（分子），偏移 0

// 向下移动（进入分母）
path.top().childIndex = FractionItem::DenominatorIndex;
navigator.moveDown(fractionItem->denominator());
// 现在在分数分母的容器中
```

## 优势总结

### 相比当前设计的优势

| 特性 | 当前设计 | 坐标路径设计 |
|------|---------|------------|
| 代码复杂度 | 高（大结构体） | 中（职责分离） |
| 扩展性 | 差（需修改结构体） | 好（新增类型无需修改） |
| 类型安全 | 一般（多个指针易混乱） | 好（单一数据源） |
| 状态一致性 | 差（多个指针需同步） | 好（单一数据源） |
| 嵌套支持 | 有限 | 无限（任意深度） |
| 维护成本 | 高 | 低 |

### 实际收益

1. **开发效率提升**：新增公式类型时无需修改核心数据结构
2. **代码质量提升**：减少指针管理的复杂性，降低 bug 概率
3. **可维护性提升**：代码更清晰，易于理解和修改
4. **功能扩展便利**：为未来支持矩阵、根式等复杂公式奠定基础
