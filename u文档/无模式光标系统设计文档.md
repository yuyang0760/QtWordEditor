## 2. 核心设计理念

### 2.1 设计原则

| 原则 | 说明 |
|------|------|
| **无模式** | 不需要切换模式，一切都是坐标路径 |
| **统一表示** | 文档和公式都用同一种方式表示 |
| **GenericMathItem 万能** | 可以放文本和公式的任意组合 |
| **坐标路径** | 用路径表示嵌套结构 |
| **自动判断** | 通过 mathPath 是否存在自动判断位置类型 |

### 2.2 核心思想

```
┌─────────────────────────────────────────────────────────┐
│                    无模式光标系统                         │
├─────────────────────────────────────────────────────────┤
│                                                           │
│  ┌──────────────┐         ┌──────────────────────┐      │
│  │  文档位置    │         │   公式坐标路径        │      │
│  │  blockIndex  │         │   (可选)               │      │
│  │  offset      │         └──────────────────────┘      │
│  └──────────────┘                                         │
│                                                           │
│  自动判断：                                                 │
│  - 没有 mathPath → 文档位置                               │
│  - 有 mathPath   → 公式位置                               │
│                                                           │
└─────────────────────────────────────────────────────────┘
```

## 3. 数据结构设计

### 3.1 光标位置结构体（NewCursorPosition - 已存在！）

**文件位置：** `include/editcontrol/cursor/NewCursorPosition.h`

```cpp
struct NewCursorPosition {
    // ========== 文档位置 ==========
    int blockIndex = -1;              // 块索引
    int offset = 0;                    // 块内偏移量
    
    // ========== 公式坐标路径（可选）==========
    std::optional<CoordinatePath> mathPath;  // 公式坐标路径
    
    // ========== 默认构造函数 ==========
    NewCursorPosition() = default;
    
    // ========== 文档位置构造函数 ==========
    NewCursorPosition(int blockIndex, int offset)
        : blockIndex(blockIndex), offset(offset) {}
    
    // ========== 公式位置构造函数 ==========
    NewCursorPosition(int blockIndex, int offset, CoordinatePath path)
        : blockIndex(blockIndex), offset(offset), mathPath(std::move(path)) {}
    
    // ========== 便捷查询 ==========
    bool isDocumentMode() const {
        return !mathPath.has_value();  // 没有路径就是文档模式
    }
    
    bool isMathMode() const {
        return mathPath.has_value();    // 有路径就是公式模式
    }
    
    bool isValid() const;
};
```

## 5. 坐标路径示例

### 5.1 示例 1：简单的 GenericMathItem

```
文档位置：blockIndex=0, offset=5
    ↓
GenericMathItem（在文档中）
    ├─ child[0]：TextSpan "123"
    ├─ child[1]：TextSpan "+"
    ├─ child[2]：TextSpan "456"
    └─ ...
```

坐标路径：
```cpp
CoordinatePath path;

// 只有一层：GenericMathItem
path.push(PathSegment(genericMathItem, 1, 0));
```

### 5.2 示例 2：分数的分子

```
文档位置：blockIndex=0, offset=5
    ↓
FractionItem
    ├─ numerator（分子）→ index=0
    │   └─ GenericMathItem
    │       ├─ child[0]："123"
    │       ├─ child[1]："+"
    │       └─ child[2]："456"
    │
    └─ denominator（分母）→ index=1
        └─ GenericMathItem
            └─ "789"
```

坐标路径：
```cpp
CoordinatePath path;

// 第一层：分数容器
path.push(PathSegment(fractionItem, 0, 0));

// 第二层：GenericMathItem（分子）
path.push(PathSegment(genericMathItem, 1, 0));
```

### 5.3 示例 3：嵌套的分数

```
文档位置：blockIndex=0, offset=5
    ↓
FractionItem（外层）
    ├─ numerator（分子）→ index=0
    │   └─ GenericMathItem
    │       ├─ "1 + "
    │       └─ FractionItem（内层）→ index=1
    │           ├─ numerator："2"
    │           └─ denominator："3"
    │
    └─ denominator（分母）→ index=1
        └─ GenericMathItem
            └─ "4"
```

坐标路径：
```cpp
CoordinatePath path;

// 第一层：外层分数
path.push(PathSegment(outerFraction, 0, 0));

// 第二层：GenericMathItem（分子）
path.push(PathSegment(genericMathItem, 1, 0));

// 第三层：内层分数
path.push(PathSegment(innerFraction, 1, 0));
```

## 8. 优势分析

### 8.1 对比表

| 方面 | 旧系统 | 新系统 |
|------|------|--------|
| **复杂度** | 高（模式切换） | ✅ 低（无模式） |
| **代码量** | 多（模式判断） | ✅ 少（无模式判断） |
| **扩展性** | 差（需修改模式） | ✅ 好（添加新类型无需修改） |
| **用户体验** | 复杂（模式切换） | ✅ 简单（无需切换） |
| **灵活性** | 差（Number/RowContainer 分开） | ✅ 好（GenericMathItem 万能） |
| **维护性** | 难（模式相关代码） | ✅ 易（统一代码） |
| **字段数量** | 多（10+ 字段） | ✅ 少（3 个字段） |

### 8.2 具体优势

1. **无模式，简单**
   - 不需要判断在什么模式
   - 不需要切换模式
   - 逻辑清晰

2. **统一表示**
   - 文档和公式用同一种方式
   - 坐标路径可以嵌套任意深度
   - 易于理解和维护

3. **GenericMathItem 万能**
   - 可以放文本
   - 可以放公式
   - 可以混合放
   - 一个类顶两个用

4. **易于扩展**
   - 新增公式类型不需要修改核心代码
   - 只需要添加新的 MathItem 子类
   - 坐标路径自动支持

5. **代码简洁**
   - 移除模式相关的复杂代码
   - 统一的处理逻辑
   - 更少的 bug

- **零模式切换**：不需要切换模式
